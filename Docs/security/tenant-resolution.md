# Tenant resolution and request surfaces

Step 13 applies the shared-schema tenant boundary to the Nest API. The dashboard uses the same-origin endpoint namespace defined by D-33. The platform-managed website key is `WEBSITE_SETTINGS.SUBDOMAIN_SLUG` under D-24. The namespaces below describe where future guarded controllers belong. Step 13 adds no website or resource routes to the production module. [Browser contract](../auth/browser-security.md) · [Website ownership](../database/website-ownership.md)

The API allocates a request ID before validating the HTTP/1.x authority and matching the namespace. The public guard resolves the published website. The private guard applies the browser boundary, authenticates the dashboard session, and joins the requested tenant UUID to an active membership for the current verified, active account. Each request selects its own tenant. Mutations require the Step 12 CSRF proof. A global interceptor requires the appropriate frozen request context before a handler can run in either tenant namespace. Nonmember, revoked, unknown, closed and deleted tenants return the same `404 NOT_FOUND` within the tenant namespace. Missing credentials use `401 UNAUTHENTICATED`. Malformed authorities and competing selectors use `400 BAD_REQUEST`. A database failure follows the standard safe 5xx path. The logs include the tenant public ID only after a successful resolution. [API errors](../api/errors.md) · [Nest request lifecycle](https://docs.nestjs.com/faq/request-lifecycle)

Tenant membership is checked on every request. An eligible onboarding member can obtain private reads. Suspended tenants retain member reads and eligible published display. The scoped resource write primitives require `TRIAL` or `ACTIVE` when each SQL statement starts. The website lookup also requires an active business, a published setting and a tenant that is neither deleted, closed nor pending onboarding. These are the Step 13 boundaries for the current projections and primitives. Booking admission, subscription expiry, grace periods and entitlement restrictions need their own approved policy and coordination. [Q-10 and D-24](../planning/decision-register.md)

Future dashboard clients should use a tenant public ID in each request path and in query, cache and invalidation keys. Clear the previous tenant's data on a switch. Keep return paths scoped, support the same stable error codes across English, Sinhala and Tamil, and provide an unavailable state on unknown hosts and a permission-denied state for authorized surfaces. Private and public Step 13 namespaces currently carry `Cache-Control: no-store`.
