# Browser authentication boundary

The owner approved `https://app.sportify.lk` as the intended production dashboard origin and `https://app.sportify.lk/api/v1` as its same-origin browser API. Configure `AUTH_DASHBOARD_ORIGIN` explicitly and preserve its Host through the reverse proxy. The implementation compares the request Host to configuration, rejects differing supplied origins, and requires the exact browser Origin on POST. The platform-admin host and tenant website hosts stay outside this boundary. Deployed ingress and source identity still require verification. [Approval](../planning/decision-register.md#d-33--step-12-policy-approval-and-isolated-oracle-verification)

Production cookies use `__Host-sportify_session` and `__Host-sportify_csrf`, `Secure`, `HttpOnly`, `SameSite=Lax` and `Path=/`. The omitted Domain attribute keeps them host-only. Logout clears both using the same scope attributes. Duplicate recognized cookie names are rejected. Deployment requires HTTPS at the browser. For explicitly enabled local HTTP development/test, choose a literal loopback origin such as `http://127.0.0.1:4000` and set `AUTH_ALLOW_LOOPBACK_HTTP=true`. This uses separate `sportify_session_dev` and `sportify_csrf_dev` cookies. Browser calls go to the API on that exact origin or use a local same-origin proxy that preserves its public Host. [Cookie behavior](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie)

Cookie scope follows the hostname even when services listen on different ports. Run local authentication checks in a dedicated browser profile with test accounts.

1. Fetch `GET /api/v1/auth/csrf` from the dashboard with `X-CSRF-Bootstrap: 1`. The server sets an HttpOnly nonce cookie and returns a signed proof. Keep the proof in memory.
2. Send the proof as `X-CSRF-Token` on login, logout, reset request and reset confirmation. A browser POST supplies Origin. Non-browser clients must send the same configured Origin, nonce cookie and proof.
3. Fetch a fresh proof after login or logout. The HMAC binds the origin, cookie nonce and current session bearer, or the anonymous state before login. Session authentication remains independently required where applicable.

Missing or null Origin fails closed on mutations. Sibling-site and cross-site Fetch Metadata are rejected when present. Missing Fetch Metadata grants no bypass. No credentialed cross-origin CORS policy is installed. A sibling browser's request requiring a custom header fails preflight. Future authenticated mutations must use the same origin and CSRF guard. [CSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) · [Nest guards](https://docs.nestjs.com/guards)

Oracle records 15-minute windows keyed by an HMAC of the socket peer. Login first consumes the source budget (default 30), then the more targeted, explicitly configured source-and-normalized-email budget. A known email alone cannot globally lock the account. Reset issuance adds the durable per-account cap and cooldown, shared across API instances. Session lookup and logout consume the separate explicit source budget before token lookup. The quota returns a bounded `429` when exhausted. Argon2id operations share a two-task process limit. The API keeps proxy trust off and treats forwarded addresses as untrusted. Behind a proxy all requests share its peer budget until a verified trusted forwarding boundary is configured. Counters store no raw address or email and a later request resets an expired window in place. Idle counter rows remain for review of an owner-only cleanup policy. [API behavior](login-and-logout.md)

Future login and reset pages need accessible labels, current/new-password autocomplete, explicit confirmation, translated stable error codes, and clear loading, retry, expired-link and rate-limit states. Keep reset fragments out of analytics, referrers and durable browser storage. Validate any future return destination on the server. The deployed ingress still needs its own HTTPS, header forwarding and sibling-host smoke checks.
