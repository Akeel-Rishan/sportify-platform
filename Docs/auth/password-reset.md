# Password reset

`POST /auth/forgot-password` returns the same accepted result for present, absent, unverified, ineligible or account-throttled addresses. The response floor reduces obvious timing differences. The request takes the account row lock before checking the rolling 15-minute issuance count and configured cooldown. Existing passwords, sessions, memberships and account states are unaffected. An eligible request atomically inserts the token digest, reference-only outbox intent and audit event.

A random UUID and independent versioned secret produce a 256-bit HMAC-SHA-256 bearer bound to the reset purpose, user ID and expiry. Issuance records the digest, UUID, key version and Oracle lifecycle. The worker reads the narrow read-only view and reconstructs an eligible link as `/reset-password#token=...` on the configured HTTPS frontend origin. The payload contains only `tokenId` and `keyVersion`. The adapter confirms the digest and reports fixed redacted outcomes. Outbound transport runs outside Oracle. [Email architecture and key rotation](email-verification.md) · [OWASP password reset guidance](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)

An eligible replacement request revokes earlier live links in the same transaction that issues its new link. A request suppressed by cooldown or the rolling cap leaves the current link and sessions intact. The first successful explicit POST consumes its link and revokes every other live reset token for the account. It updates the password hash, revokes existing sessions across audiences and writes audit plus a reference-only completion event. It leaves verification, account status and membership intact. The user logs in again with the new password. Unusable links receive a generic `400`. A blocked new password receives the same policy response as verification. Neither GET nor an email scanner consumes a link.

The approved configurable defaults are 30-minute links, a 60-second cooldown and up to three issuances per account in a rolling 15-minute window. Revoked and consumed issuances still count toward the cap. Default source limits are 10 requests and 30 confirmations per 15 minutes. The enabled API still requires a reviewed `AUTH_RESET_OUTBOX_MAX_ATTEMPTS`. Key versions and opening the feature to live users require operator review. [Approval](../planning/decision-register.md#d-33--step-12-policy-approval-and-isolated-oracle-verification)

The controlled loopback transport can verify message reconstruction locally. The Step 11 external dispatcher, provider acceptance and inbox gates still apply to live reset delivery. Each future dispatch must use the purpose-specific adapter, refresh token eligibility before sending and keep raw URLs and recipients out of telemetry.
