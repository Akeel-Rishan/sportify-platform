Origin labels below identify source/proposed provenance and do not override this scoped approval. The scoped 26-table release is now installed and catalog-verified on the designated Oracle target; 33 specific integrity cases passed. Broader future tables remain uninstalled proposals. Original uploads and unrelated future table definitions are preserved.

Approved resource rules: SLOT_INTERVAL_MINUTES is fixed at 15; owners can configure positive minimum/maximum booking duration bounds in multiples of 15 and nonnegative before/after buffers in multiples of 15. Actual booking starts, durations and buffer occupancy must be enforced by the later authorized booking transaction, not by claiming these configuration tables implement bookings.

## Universal column rules

- Oracle 19c-compatible syntax, AL32UTF8 target to verify; every VARCHAR2/CHAR declares CHAR semantics explicitly. Limits are characters but Oracle byte/index limits still apply. NUMBER without precision means Oracle unconstrained NUMBER, not a JavaScript number; identity generates integral values and positive integer checks protect entity PKs. All identifiers are fetched/bound as exact decimal strings using a reviewed node-oracledb fetch strategy, never first rounded through JS Number. APIs expose UUIDs/stable codes rather than these internal IDs.
- UUID columns are VARCHAR2(36 CHAR), lowercase hyphenated UUIDv4; generation is cryptographic in the application. Global roots have global unique public IDs; tenant entities use (TENANT_ID,PUBLIC_ID), mixed audit IDs are globally unique. Natural keys remain sports/plan codes and tenant-qualified invoice/reference codes. Association tables keep natural composite PKs.
- TIMESTAMP(6) *_UTC holds UTC absolute instants; initialize every connection session to UTC and verify checkout state. LOCALTIMESTAMP defaults require UTC sessions. Creation times are DB defaults, updated times must explicitly be set from database UTC time in the write statement (a DEFAULT does not auto-update). Event instants are server-validated and use database time where authoritative; client payment occurrence times are range-validated separately. DATE HOLIDAY_DATE is a local calendar date at midnight.
- For non-LOB character columns Oracle zero-length string becomes NULL. Trim at input; required blank/whitespace values are rejected before binding, optional empty input is explicitly normalized to NULL. CLOB empty locators are distinct and require content-length validation; do not use empty text to bypass required policy/body content.
- Email normalization: trim and lowercase entire address under the agreed API policy, no provider alias rewriting. USERS global normalized email is unique (registration requires email even though optional schema supports legacy identities); CUSTOMERS email/mobile are nonunique tenant search keys, never proof of identity or automatic merge. Do not auto-link a guest to USERS. Invitation email matches the authenticated accepting account; application authorizes linking.
- E.164 fields contain + followed by at most 15 digits; use a proven phone parser at the future API boundary, not numeric storage. Slugs/hostnames use lowercase ASCII, reserved-name rejection, trailing-dot normalization and trusted suffix checking. SUBDOMAIN_SLUG is one DNS label, <=63 characters; full hostnames <=253. Public routing uses only platform suffix + this globally reserved slug.
- Token hashes are lowercase SHA-256 hex64 in existing 128-char columns (extra capacity is not permission for other encodings); random tokens must have >=256 bits. Password hashes store Argon2id encoded verifiers. The Q-09 proposed deterministic HMAC token/replay design stores only digests, public random record IDs and key version; keys remain outside Oracle. No raw bearer value in replay, outbox, job, audit or notification body columns.
- Exact monetary range for NUMBER(12,2) is up to 9999999999.99 magnitude. Scale/range are checked before binding because Oracle may round excess fractional input. Use decimal strings/minor-unit integer arithmetic; currency format is uppercase three letters, initial supported currency LKR. See [finance](financial-rules.md).
- Column validation responsibility includes DB type/null/key/check guarantees and APP canonicalization, authorization and transactional cross-row rules. A value fitting VARCHAR2 is not a validated email/URL/name. No public example is a real credential or personal record. Examples: UUID 76e07868-3e3a-41f8-9dd6-382445f59d57, email owner@example.invalid, money "5000.00", local zone Asia/Colombo. Hash examples are format descriptions rather than usable tokens.
- All proposed amendments require design acceptance. Source-supported status values not enabled in MVP remain dormant; this dictionary does not activate a workflow. Exact state transitions are owned by [booking](booking-invariants.md), [finance](financial-rules.md), and [operations](operational-data.md).

Supported MVP language codes are `en`, `si`, and `ta`; DEFAULT_LANGUAGE and notification LANGUAGE_CODE are validated against this application allowlist. This does not implement localization or imply a DB CHECK where none is listed.
