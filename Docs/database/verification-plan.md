# Database design verification and future Oracle tests

Step 05 checks documents/structure only. No SQL is executed and no Oracle connection is opened. Test IDs below are future acceptance work, not completed test claims.

## Repeatable local design checks

From repository root, with Python 3.10+ (local review used 3.14):

```sh
python database/design/verify-design.py
npx --yes pnpm@10.34.9 format:check
git diff --check
```

The checker uses the standard library, reads the preserved SQL catalog and the actual Markdown dictionary/key/index registers, and creates no files. It is not a migration runner or an Oracle SQL parser. It checks every source disposition, included source column preservation, complete per-table metadata/column cells, exact FK arity/type/parent keys, non-null tenant keys, slot PK/XOR/resource owners, leading FK index coverage/exact duplicate indexes, dependency cycles, included ERD entities/edges/column types, requirement references and Markdown targets/anchors. Names and status expressions still require semantic review and Oracle compilation. No testing framework is installed for Markdown.

Three Mermaid diagrams are rendered through an isolated temporary Mermaid CLI/Chrome profile for syntax and visual inspection; renderer dependencies are not repository dependencies and outputs stay under ignored tmp. A legacy transient Puppeteer dependency warning is an artifact-tool limitation, not an application package change. Source upload and application hashes are compared before/after; application tests are not rerun merely to validate design-only edits.

Review beyond mechanical checks: compare state vocabularies with dictionary CHECKs; trace the single locking hierarchy through every transaction; review explicit UTC/buffer/rounding/refund/retention proposals; verify no deferred table enters an FK/diagram; and inspect conditional CHECKs for NULL/UNKNOWN bypasses. Design checker success does not prove race freedom, SQL validity, Oracle behavior, security or performance. Actual executed counts/results are recorded in [progress](../planning/progress.md).
